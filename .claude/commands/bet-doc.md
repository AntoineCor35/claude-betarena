Update project documentation for the current or recently completed feature.

## Instructions

1. Read `.planning/STATE.md` to identify the feature.
2. Read `.planning/<feature>/PLAN.md` to understand what was built.
3. Read `.planning/<feature>/TRACKING.md` for the full summary of each phase.
4. Scan the modified files to understand the implementation.
5. Decide what needs updating:
   - `README.md` → if the feature is user-facing
   - `docs/<module>.md` → if a new module, service, or complex system was created
   - Inline comments → only if there's complex logic that isn't self-explanatory
6. Make the updates — keep them short and honest:
   - What the feature does (1-2 sentences)
   - How to use it (code example or steps if relevant)
   - Any gotcha or limitation
7. Show the user what was changed and ask for approval before saving.

**If `prof` is in $ARGUMENTS:** explain what makes good documentation, show a before/after comparison, and explain why each section matters.
